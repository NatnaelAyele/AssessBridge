# Safe Exam Browser configuration

New invitations store their password-encrypted SEB configuration and Config Key in MySQL. Their email links to a normal HTTPS launch page, where the candidate chooses **Open in SEB** or downloads the configuration file. Configuration passwords and emergency quit codes are eight characters and specific to the invitation.

Before opening SEB, candidates register and verify the invitation email in a regular browser. Inside SEB they sign in to that candidate account, then enter the separate exam-only credentials. The server checks the approved Config Key at entry and on exam, recording and recovery APIs. Modern clients supply the URL-bound proof through the JavaScript bridge; native proof headers are also supported. A SEB user-agent string alone grants no access.

Candidates can exit before starting without losing an attempt. An explicit **Exit SEB** action during an unsubmitted exam records the choice and disqualifies that attempt. Missing heartbeats alone do not prove a voluntary quit: they enter bounded recovery, with a fresh face check required for session recovery. Current limits are three minutes per interruption and ten minutes total. The server timer continues and submits saved progress when the exam deadline is reached. Recovery-limit exhaustion records an interrupted attempt. After submission, the normal **Exit exam** action waits for recording collection to finish; an emergency native quit remains under the candidate's control.

The generic `AssessBridge.seb` file supports legacy invitations. For local development, configure a strong `JWT_SECRET`, then run `python backend/make_seb_config.py --base-url http://127.0.0.1:8000` and restart FastAPI. This updates the local `.env` and generic file; existing per-invitation files retain their original addresses and passwords.

The hosted deployment uses `https://natnael.tech` and permits navigation to `identity.natnael.tech` for eSignet. Its generic file is generated under `/etc/assessbridge/seb/` and mounted read-only into the API. Protected configuration belongs in the server environment, never Git. See the root deployment plan for execution and validation status.

The installed Windows SEB 3.10.2.920 configuration library decrypts both hosted configurations and computes the same Config Keys as the server. On 18 November 2026, the public Windows workflow passed: exit before sign-in, candidate login, camera/microphone access, eSignet authentication, exam submission, completed recording upload and final exit. Server records confirm identity verification, submission, recording completion and completed monitoring analysis. macOS integration is implemented but has not been validated on a Mac; the initial supported pilot is Windows.
